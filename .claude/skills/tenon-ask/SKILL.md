# 带引用回答项目问题

<!-- 由 tenon 生成；tenon update 会覆盖本文件 -->

## 步骤

1. 判断问题类型：
   - 定位或取值类（"X 在哪里""默认值是多少"）：直接用 `rg` 或 Grep 搜源码，不必读知识页。
   - 跨模块流程、"为什么这样设计"、历史变更：先读 `.tenon/knowledge/index.md` 和相关知识页，把它们当线索，再打开需要的源码。
2. 回答中的每条事实都要在源码中亲眼看到过；知识页只是线索。两者不一致时以源码为准。
3. 搜不到时至少换两种关键词（中文与英文、类名、URL 片段、表名）。
4. 怀疑知识页过期时运行 `tenon wiki lint --json`；页面 stale 时只信源码，并在回答中说明。
5. 作答。

## 回答格式

- 先给结论，再给依据。
- 每条关于本项目的事实后写出处：`path:行号` 或 `path#符号`，path 为仓库内相对路径。
- 代码中找不到依据时，明确回答"未知：代码中未找到"，并列出搜索过的关键词与位置。不要用通用经验推测本项目的实现。
- 不编造文件名、类名、配置值。

## 规则

- 只读，不修改任何文件。
- 发现知识页与源码不一致时，在回答末尾说明，并建议用 tenon-scan 更新。
