### 实现要点

- delta 格式与 OpenSpec 一致。每条 ADDED / MODIFIED 需求必须有 SHALL / MUST（或"必须"）和至少一个 `#### Scenario:`。validate 会对当前规范做合并试算：ADDED 重名、MODIFIED / REMOVED 不存在、新能力用了 MODIFIED，都在审批前报错。
- render 把被审文件拼成 am 草稿，以子进程调用随包的 am，使用独立的 `AM_HOME`，不碰用户自己的 am 配置。安全规则：
  - 拒绝 html / svg 块、带属性的代码块（防止 `src=` 嵌入本地文件）、`:::` 块和图片；
  - 正文中的 `<`、`>` 转义（行内代码与代码块除外）；
  - 渲染前后各算一次哈希，不一致就报错。
- 审查页面板：A 提案、B 规范增量（新增绿、修改黄、删除红）、C 设计、D 任务表格与自动依赖图、E 被审文件清单与完整哈希。
- 在浏览器中核对过：`<script>` 显示为文本，D、E 面板内容完整。
