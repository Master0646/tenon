与设计稿的差异（已回写 v0.2 文档）：

- `diff_hash` 改为工作树的 git 树哈希（临时索引 + `write-tree`），暂存或提交不会让验证失效。
- `approve` 允许从 `draft` 或 `rebase_required` 发起；开工、验证记录只认最近一次批准之后的。

§14 核对结论：

| 项 | 结论 |
| --- | --- |
| Claude Code shell 是否 TTY | 否（本会话实测），TTY 防线有效 |
| Codex shell 是否 TTY | 由模型通过 `exec_command` 的 `tty` 参数决定（源码），TTY 防线可被绕过 |
| Codex 技能目录 | `<repo>/.agents/skills/<name>/SKILL.md`，`$name` 调用 |
| Codex 命令禁止 | `.codex/rules/*.rules` 的 `prefix_rule(decision="forbidden")`；需项目被信任；实验性 |
| Claude Code 命令禁止 | `.claude/settings.json` 的 `Bash(devflow approve *)`，对复合命令的每个子命令生效 |
| Codex 实测 | 未完成：本机 Codex 默认模型 `gpt-6.1-sol` 与指定的 `gpt-5.5` 都返回"ChatGPT 账号不支持该模型" |
