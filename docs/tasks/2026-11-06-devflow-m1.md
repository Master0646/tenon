# DevFlow M1：项目知识

## 目标

按 `../DevFlow-v0.2-系统设计.md` §6、§9、§10 M1 交付：

- `devflow wiki lint`：校验知识页 frontmatter、引用路径与符号、排除路径、index.md 覆盖、页面链接；按 git 判定过期。
- `devflow init --agents claude,codex` 与 `devflow update`：生成 scan / ask 技能、AGENTS.md 与 CLAUDE.md 入口片段、Claude Code 与 Codex 的禁止规则。
- 简化演示项目（Spring Boot + MyBatis + Vue）与 20 道题的评测集、自动评分脚本。
- 用 `claude -p` 跑一遍评测，记录基线。
- 在 devflow 仓库自身启用 DevFlow。

- scan：32 轮，生成 3 页（用户管理、认证与会话、接口约定与运行配置），wiki lint 无错误。
- 准确率 65% 的原因：回答常顺带引用相关周边文件（如问 401 处理时引用 AuthInterceptor），没有编造。题库 v1 的 `ok` 清单保持不变，不按回答回调题库。
- 阈值建议（待确认）：召回 ≥ 90%，"未知"题拒答 = 100%，找不到的引用 = 0；准确率只看趋势，不设硬门槛。

### 评测中发现并修复的问题

- `index.md` 模板注释里的示例链接被当成真实页面 → 解析前去掉 HTML 注释。
- 知识页正文引用了未列入 `sources` 的文件，3 页全有 → 新增 lint 警告，scan 技能要求处理。
- 评分脚本不认 `../views/X.vue` 这类 import 路径 → 去掉 `./`、`../` 前缀后按后缀匹配。
- 第一次探针无效：模型按 CLAUDE.md 自行拒绝，命令没到权限检查 → 探针改在只含 `.claude/settings.json` 的目录运行；实测 `Bash(devflow approve *)` 被拦截（$0.07）。
- `templates/skills/.DS_Store` 被当成技能复制 → 只复制含 SKILL.md 的目录。

### 对照组（2026-11-06，`eval/results/2026-11-06-04-11-control/`）

不装 DevFlow，同样 20 题；"带引用、查不到答未知"的要求放进系统提示，与 DevFlow 组的入口片段一致。

| 指标 | DevFlow 组 | 对照组 |
| --- | --- | --- |
| 引用召回率 | 100% | 100% |
| 引用准确率 | 65% | 66% |
| "未知"题拒答率 | 100% | 100% |
| 找不到的引用 | 0 | 0 |
| 每题平均轮数 | 8.4 | 5.3 |
| 每题平均花费 | $0.152 | $0.115 |
| 一次性 scan 花费 | $0.64 | — |

结论：

- 在 25 个文件的演示项目上，知识页**没有提高准确率，反而多花轮数**：DevFlow 组 18 题轮数更多，0 题更少，2 题相同。
- 多出的轮数来自入口片段与 ask 技能的强制顺序："先读 index → 读知识页 → 打开 sources 核对 → 再搜索"。小项目里直接搜代码更快。
- 准确与拒答两组相同，说明这两项主要来自"带引用、答未知"的提示要求，而不是知识页。
- 题库 v1 只考"代码里直接能搜到"的事实，这类题本来就不需要 Wiki。每组只跑了一次，没有统计方差。

### v2 重测（2026-11-06，`eval/results/2026-11-06-04-17/` 与 `2026-11-06-04-22-control/`）

改动：入口片段与 ask 技能改为"按需读知识页"；题库加 7 道跨文件推理题（q21–q27），评分增加结论正则。

| 指标（27 题） | DevFlow 组 v1 → v2 | 对照组 v2 |
| --- | --- | --- |
| 引用召回率 | 100% → 100% | 100% |
| 引用准确率 | 65% → 71% | 74% |
| 推理题结论正确率（7 题） | — → 100% | 100% |
| "未知"题拒答率 | 100% → 100% | 100% |
| 每题平均轮数 | 8.4 → 6.0 | 4.8 |
| 每题平均花费 | $0.152 → $0.127 | $0.106 |

结论：

- "按需读"把额外开销从约 60% 降到约 25%（轮数：DevFlow 组更多 12 题、更少 5 题、相同 10 题），但仍没有反超对照组。
- 跨文件推理题两组都全对（抽查 q23、q26 的回答，结论与依据都正确）。在 25 个文件的项目里，Agent 直接读代码就能串起调用链，知识页没有信息优势。
- **对产品方向的含义**：在小项目上，"知识页帮 Agent 查代码"不成立。DevFlow 知识层的价值只可能来自：
  1. 大项目——Agent 读不完代码时的导航作用（未测）；
  2. 代码里看不出来的知识——设计原因、历史变更，由 M2/M3 的归档产生（未测）；
  3. 跨会话恢复变更状态——这已由规范、事件日志和派生状态承担，不依赖知识页。
- 因此暂停对"查代码型" Wiki 的投入：scan 保留但不作为必需步骤；下一轮知识评测放到 M3 之后，题目考设计原因与历史变更，并在真实的大项目（如 aags）上本地跑。

本轮花费：DevFlow 组 $4.07（scan $0.64 + 作答 $3.43），对照组 $2.87。
