# 审查页去文字墙（体验反馈第 4 批）

## 为什么

- #26：审查页基本是 markdown 原样转换，spec 每条场景都是长句，验收条件挤在一个表格单元格里。
- #26：Agent 写的 proposal、design 段落很长，审查页没有任何约束。
- #27：审完页面要切到终端，手敲 `devflow approve <id>`，再对一遍 64 位哈希。

## 改什么

- 规范增量：每条需求显示为"需求名 + 约束一句 + 场景表（场景 / WHEN / THEN）"。
- 任务：每个任务一张小卡片（标题、依赖、验收条件逐条列出），保留依赖图。
- validate：proposal.md、design.md 中超过 3 句的段落给出 warn。
- 审查页 E 面板给出完整命令 `devflow approve <id> --hash <12 位>`，可直接复制。
- `approve --hash`：哈希前缀与当前内容一致才批准，并跳过 y 确认；不一致直接拒绝。

## 影响

- 审查页的 B、D、E 三个面板版式变化，内容不变。
- 不带 `--hash` 的 `approve` 行为不变。

## 不做什么

- 不做长段落折叠：am 没有折叠组件，审查页又禁止原始 HTML。改为 validate 提醒。
- 不做"接口变更自动汇总表"：变更文件里没有结构化的接口信息。
- 不改"批准只能在交互终端运行"的规则。
