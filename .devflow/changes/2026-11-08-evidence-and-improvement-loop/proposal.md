# 验收证据与持续改进闭环

## 为什么
- 任务完成声明、项目测试成功与需求验收之间缺少可核对的连接。
- 重新批准、实施调整和共享工作树的规则增加重复确认，并可能沿用旧完成记录。
- 使用反馈与评测尚未形成从发现问题到验证改进效果的固定路径。

## 改什么
- 为新变更引入带编号的验收条件、验证证据与统一审批周期。
- 保留业务契约审批，将非契约实施笔记单独记录，并提供审批差异与继续工作摘要。
- 新变更在同一工作树中串行开工，并对规范冲突给出可操作的恢复路径。
- 本地自动记录命令使用结果，关联人工反馈、故障回归和优化变更。
- 按五个阶段、T1–T11 交付，以工程正确性、兼容性和离线成本测试验收。

## 影响
- CLI、变更格式、事件解析、审查页、三个流程技能和评测入口需要升级。
- 旧变更保留旧格式与批准哈希，新格式须升级 CLI 后使用。
- 运行记录默认本地保存，可关闭；不自动上传或调用付费模型。

## 不做什么
- 原 T12 的闭环演示与真实 Agent 收益评测已移至后续变更 2026-11-08-agent-workflow-evaluation；本次归档不代表真实收益已验证。
- 本轮不建设全仓知识页，不增加云端平台或自动改代码的自优化代理。
- 不承诺自动证明业务正确，不通过缩小工作树哈希来减少重验。
- 不提供 worktree 创建器或跨分支自动合并器，复用 Git 与现有 Agent 能力。
