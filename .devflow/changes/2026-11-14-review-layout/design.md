# 设计

## 页面结构

```tree
变更页（审查台）
  顶部操作栏 .df-bar（固定在顶部）
  左侧目录 .df-toc（固定）
  正文
    首屏：进展与待办
    方案要点与影响范围
    批准差异（重新批准时才有）
    验收矩阵（有证据时才有）
    A 提案 … E 被审文件
    批注记录（只在审查台）
```

- 正文面板的生成都在 `buildDraft`（`src/render.ts:98`）。目录、操作栏、批注记录的脚本和样式由 `actionBar`（`src/review.ts:335`）注入，离线页不带。
- 渲染器自带的右侧大纲（`.am-toc`，`vendor/answer-me-with-html/am.mjs:517`）在审查台里隐藏，用新目录代替；离线页照旧。

## 首屏：进展与待办

- 现在的首屏面板（`src/render.ts:118`）拆成两个：
  - 「进展与待办」：进度条、当前工作节点、要你做什么、待拍板事项。
  - 「方案要点与影响范围」：现在首屏里的 `### 方案要点` 和 `### 影响范围`，默认展开。
- 进度条分 5 段，由工作节点（`2026-11-14-workbench-progress` 的 `workNode`）映射：

| 段 | 工作节点 |
| --- | --- |
| 方案 | 写方案中 |
| 批准 | 待你批准 |
| 实现 | 待开工、实现中 |
| 验证与证据 | 补证据中、修复中/待重新验证、待你确认 |
| 归档 | 归档准备中、待你归档 |

- 进度条用 Markdown 表格的一行生成，当前段加粗、之前的段打勾，不注入 HTML。
- 「要你做什么」按节点写一句话：待你批准是「选好 N 个待拍板事项后点批准」，待你确认是「核对 N 条人工证据后点确认」，待你归档是「点归档」；其余节点是「现在不需要你操作：Agent 正在<节点>」。

## 目录

- 目录脚本在页面加载后读取每个 `.am-panel` 的字母徽标和 `h2` 文字，生成链接列表。括号里的面板状态（如「与上次批准相同」）原样显示在标题下面一行。
- 点链接时：先给折叠的面板去掉 `df-closed`，再 `scrollIntoView`，并把顶部操作栏的高度用 `scroll-margin-top` 让出来。
- 当前面板高亮：用 `IntersectionObserver` 观察面板标题，最靠上的可见面板标为 `aria-current`。
- 宽度不小于 1024px 时，目录固定在左侧，宽 220px，正文向右让出位置。更窄时按拍板结果处理（推荐：收成操作栏下方一行横向滚动的标签）。

## 顶部操作栏

- `.df-bar` 从 `bottom:0` 改为 `top:0`（`src/review.ts:139`）。`body` 的 `padding-bottom:72px` 改为 `padding-top`，并修正批注按钮浮层的定位。
- 栏内顺序：← 全部变更、工作节点、原因、操作按钮、发送批注、Agent 等待状态、消息。

## 批注记录

- `feedback.ts` 新增 `listFeedback(root, id)`：读取未读目录和 `read/` 下的全部发送记录，按时间排序，返回 `{ at, read, items }[]`。坏文件跳过。
- `renderHtml` 增加一个可选参数，由审查台传入批注记录，`buildDraft` 据此在最后加「批注记录（N 条）」面板。表格列为：时间、面板、引用原文、意见、状态（Agent 已读/未读）。
- 所有字段经现有的 `cell` 转义后进表格（`src/render.ts` 的 `cell`、`escapeInline`），不拼原始 HTML。
- 批注记录不进被审文件，不影响内容哈希。没有批注时不显示这个面板。
